# Smart Backlog Series Search

Smart Backlog Series Search is feasible as a cache refresh strategy. An opted-in Torznab provider can issue a canonical-title query and make its matches available to later season segments. Coverage depends on the indexer's response contract. An RSS feed alone provides no evidence that its underlying search finished.

## Medusa execution path

The base is `c792e19b2638d6750dcd21bd6f710343a7381d9a`, shared by `origin/develop` and `upstream/develop`.

- `medusa/search/backlog.py` calls `Series.get_wanted_segments(from_date=...)`. The Series model queries by indexer and series ID and applies `Quality.should_search` to episode status, quality and the manual-search flag. The scheduler queues one low-priority `BacklogQueueItem` per season and skips paused series.
- `medusa/search/queue.py` calls `search_providers` in `medusa/search/core.py`. Enabled providers are visited in configured order. The backlog uses cached candidates first, then calls `find_search_results`. Daily, manual, failed and proper searches have their own entry points or flags.
- `GenericProvider.find_search_results` in `medusa/providers/generic_provider.py` generates episode queries inside its episode loop. Season-pack mode uses the first episode's season templates and exits the loop. `TorznabProvider.search` can send indexer IDs with season and episode in `tvsearch`, then retry as free text. Legacy mode mutates parameters within a search call. The new title query builds each page's parameters independently.
- `NameParser` in `medusa/name_parser/parser.py` uses GuessIt, the normalized name cache, indexed titles, scene exceptions and scene numbering. Legacy results carry `result_wanted` and `add_cache_entry` flags. Parsing failures clear both. Some parsed but unwanted releases remain cacheable. `TorznabProvider.search` returns accepted rows as a list. An empty list can mean an empty feed or a request failure. `MedusaSafeSession` normally consumes request exceptions.
- `SearchResult` in `medusa/classes.py` carries the series and `actual_season` with `actual_episodes`. The cache serializes them in the provider's existing SQLite table with both `indexer` and `indexerid`. `Cache.find_episodes` filters on all three plus episode membership and reconstructs the result. `episode_number` then becomes a bare episode number or a pack sentinel. `list_results_for_provider` and `collect_single_candidates` use that key, and `collect_multi_candidates` uses the sentinels. `combine_results` resolves overlap using Episode objects. Passing two seasons through one candidate collection would conflate equal episode numbers.
- `filter_results` and `pick_result` apply search delay, series quality and upgrade rules, anime groups, sources, words and failed history. A selected candidate becomes a `SnatchQueueItem`, whose normal client path records episode status and history. The original snatch queue checks matching show and segment. Smart candidates additionally check pending episode overlap, matching content in the queue and its bounded success history, and eligibility at execution. Medusa's persisted history has release names and episode identities. The new content check does not persist a hash index.

aMuTorrent dispatches ED2K global and Kad legs sequentially in a Torznab FIFO. Each leg takes the manager's shared search lock without keeping the EC download-add path blocked. ED2K has a default five-second spacing and settle time. Kad gets no ED2K rate delay. Polling defaults to one second, the search deadline to 120 seconds per leg and lock wait to 180 seconds. A disconnected request drops its subscription. The server cancels shared work when the final subscriber disconnects.

Both legs contribute results keyed by hash and combine alternate names. The server caches completed searches including zero results, and excludes refused or timed-out searches from its server-side cache. Partial rows can still appear in HTTP 200 RSS. A missing daemon can produce HTTP 200 with an empty feed. Handler exceptions can produce an RSS body with HTTP 500, and the API module separately checks API keys. The handler slices the hash list by offset and limit, then `search.js` expands each distinct filename into its own XML item. The XML has no offset, total, snapshot or completion field. The source tests `torznabSearchCaching`, `torznabSearchDedup`, `torznabSearchQueue` and `torznabQueryBuilding` cover these behaviors at the handler level. Inspected code includes `server/modules/amuleManager.js` and `server/modules/torznabAPI.js`.

Sonarr and SickGear use GPLv3 licenses and aMuTorrent uses MIT. The Medusa changes were written independently.

## Initial implementation

- Enable the provider's backlog normally, then set `<provider_id>_smart_backlog = 1` in the provider's existing section in `config.ini`. The provider API also serializes the Boolean as `config.search.backlog.smartSeriesSearch` and accepts it in the provider settings payload. It defaults to false. The UI has no new control.
- Only scheduler-created backlog items carry the cross-season date window. The scheduler cutoff limits threshold counting. Existing user-triggered episode requests and manual, failed, daily and proper search routes keep their usual behavior.
- The coordinator reads season-local cache candidates first and tests the five-episode threshold against unresolved eligible episodes. It keeps an entirely covered segment local. When fewer than five episodes are unresolved across the series, the segment uses the legacy path without a broad attempt. Any episode still unresolved after a broad attempt, or during its retry window, also uses the legacy path, which reads the refreshed cache first. Coverage therefore never drops below the legacy search. Snatched episodes that still want an upgrade are searched by the legacy path, since a smart result never replaces a pending snatch. Providers that advertise no free-text support use the legacy path.
- The Torznab transport preserves categories and credentials, never sends a blank query, and sends fresh title-only parameters. It uses the existing Medusa session timeout and proxy/TLS settings, with response URL logging, redirects and Cloudflare retries disabled on these requests. The first uncached capability lookup costs one request. Five search pages are the upper bound. A valid channel-level Torznab or Newznab response offset and stable total allow the next page. Bad offsets, repeated pages, HTTP/XML errors and budget exhaustion stop paging. Offset advances by the requested page size, independent of emitted XML row count. With no response metadata it takes the first page only.
- The coordinator stores provider ID, indexer and series ID, scope, normalized title, monotonic last attempt and retry deadline. It permits one active broad search per provider instance, with the lock released during transport, parsing and database work. A bounded 256-entry process-local map prunes expired entries on new work. Five-minute suppression applies to unknown, partial and failed attempts. Standard Torznab provides no confirmed-completion signal, so this implementation has no confirmed-success timestamp or 24-hour cooldown. Even the final advertised page has unknown completion.
- The parser independently resolves each filename and verifies its series and episode coordinates. It rejects known title collisions, unnumbered non-anime results and content with conflicting mappings within the response. Air-date matches require a unique local regular episode or a unique special when there is no regular episode. Valid releases, including other seasons, use the existing cache. Alternate filenames survive parsing and quality selection. The ordinary candidate pipeline only receives one season at a time. Smart candidates require every contained episode to be eligible, including for packs. Cache writes alone do not create snatch jobs.

## Follow-up and limits

A separate aMuTorrent change is unnecessary for first-page retrieval. To support reliable continuation, aMuTorrent should expose offset and total in **underlying hash units**, an opaque snapshot identifier stable across pages, and explicit status for complete, partial, unavailable and refused searches. Other mechanisms of truncation, including Kad and ED2K result caps, still need coverage semantics.

Medusa follow-up work includes bounded season/year/alias refinement, a fair targeted budget, optional durable attempt state, and a provider UI control. Live aMuTorrent verification should check timeout behavior and the distinct HTTP, ED2K and Kad counts. The existing parser can refresh scene numbering as part of matching. This is outside the Torznab page count. Content duplication is checked by magnet BTIH or exact URL in the active queue and its recent success history. Persistence across restarts, different opaque URLs for the same content, and deeply conflicting mappings across separate queries are outside the foundation. Shared cache writes use the existing SQL batch path, including its potential concurrent-identifier collision behavior. The strategy can retry after that error without starting targeted searches.
